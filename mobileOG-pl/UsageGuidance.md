# Description:

mobileOG-pl. v. kyanite is a lightweight mobile genetic element annotation pipeline using the mobile orthologous groups database (https://mobileogdb.flsi.cloud.vt.edu/). It takes a set of contigs or long reads as input and produces:

1)	Open reading frames using prodigal
2)	Alignment summaries to a mobile orthologous groups database file using diamond
3)	Element-mapping data summarizing matches to proteins from different element classes. 

This pipeline reports the presence of MGE proteins in a set of contigs using mobileOG-db annotations. It provides protein hit classifications as being putatively derived from plasmid, phage, insertion sequences, and/or integrative genomic element. Thus, mobileOG-pl can be used as the basis for detection of any major class of bacterial MGE and can be complemented with other tools to achieve a fine-grained element classification. 



# Quick-start guide:
## Dependencies: 

python 3.6.15 with pandas, argparse, itertools

prodigal 

diamond 0.9.24 or greater

1.	 Install Conda environment:

	conda create -n mobileOG-db python=3.6.15

	conda activate mobileOG-db

	conda install -c conda-forge biopython

	conda install -c bioconda prodigal
	
	conda install -c bioconda diamond
	
	conda install -c anaconda pandas

2.	 Download mobileOG-db (From Website)
	
		Database (mobileOG-db-beatrix-1.X.All.faa)
	
		Metadata (mobileOG-db-beatrix-1.X.All.csv)
	
		Code (mobileOGs-pl-kyanite.sh and mobileOGs-pl-kyanite.py)
	
		
	mkdir mobileOG-db_workdir
	cd mobileOG-db_workdir
	
	chmod +x mobileOGs-pl-kyanite.sh
	
	PATH_TO_DOWNLOAD=download link

	wget $PATH_TO_DOWNLOAD 

	DOWNLOADED_ZIP=downloaded zip file

	unzip $DOWNLOADED_ZIP

3. 	Make Diamond Database:

	diamond makedb --in mobileOG-db-beatrix-1.X.All.faa -d mobileOG-db-beatrix-1.X.dmnd

4. 	Run Code (example of stringent settings):

	conda activate mobileOG-db
	
	chmod +x mobileOGs-pl-kyanite.sh
	
	./mobileOGs-pl-kyanite.sh -i test.fasta -d mobileOG-db-beatrix-1.X.dmnd -m mobileOG-db-beatrix-1.X.All.csv -k 15 -e 1e-20 -p 90 -q 90
	
5. 	Usage:

	-i, --input | Input Fasta File
	
	-k , --kvalue | Number of Diamond Alignments to Report
	
	-e, --escore | Maximum E-score
	
	-d, --db | Diamond Database
	
	-m, --metadata |  mobileOG-db metadata (csv file) used to compare to samples
	
	-p, --pidentvalue |  Percent of Identical Matches of samples to metadata
	
	-q, --queryscore |  Percent of query coverage to sample

# April 2026 Update - Enhanced CLI Options

The pipeline scripts (`mobileOGs-pl-kyanite.sh` and `mobileOGs-pl-amethyst.sh`) have been updated with additional command-line options to improve flexibility and usability.

## New Options

### `-h`, `--help`
Display a help message listing all available options and exit. This replaces the previous behavior where the script would silently exit when `-h` was passed.

### `-o`, `--out`
Specify a custom **output directory** for all generated files. If the directory does not exist, it will be created automatically. If omitted, all files are written to the current working directory (default behavior).

**Output files include:**
- `${sample}.faa` — Predicted protein sequences (skipped if `--faa` is provided)
- `${sample}.tsv` — Diamond BLASTP alignments
- `${sample}.mobileOG.Alignment.Out.csv` — Parsed alignment output
- `${sample}.summary.csv` (kyanite) or `${sample}_temp_summary.csv` (amethyst) — Final summary statistics

### `--faa`
Provide a **pre-computed protein FASTA file** (e.g., previously generated by `prodigal`). When this option is used, the pipeline **skips the prodigal gene prediction step** and proceeds directly to Diamond alignment. This is useful for:
- Re-running analyses on existing protein sets
- Incorporating custom ORF predictions
- Saving compute time on large datasets

> **Note:** The protein FASTA must be formatted compatibly with the downstream parsing scripts (e.g., containing `prodigal`-style headers with `#` delimiters).

## Updated Usage

```
-i, --input         | Input nucleotide FASTA file (required)
-o, --out           | Output directory (default: current directory)
--faa               | Pre-computed protein FASTA file (skips prodigal)
-k, --kvalue        | Number of Diamond alignments to report
-e, --escore        | Maximum E-score
-d, --db            | Diamond database
-m, --metadata      | mobileOG-db metadata (.csv) used to compare to samples
-p, --pidentvalue   | Percent of identical matches
-q, --queryscore    | Percent of query coverage
-h, --help          | Show help message and exit
```

## Usage Examples

### Standard run (with prodigal prediction)
```bash
./mobileOGs-pl-kyanite.sh \
  -i test.fasta \
  -d mobileOG-db-beatrix-1.X.dmnd \
  -m mobileOG-db-beatrix-1.X.All.csv \
  -k 15 -e 1e-20 -p 90 -q 90
```

### Redirect all outputs to a custom directory
```bash
./mobileOGs-pl-kyanite.sh \
  -i test.fasta \
  -o ./results \
  -d mobileOG-db-beatrix-1.X.dmnd \
  -m mobileOG-db-beatrix-1.X.All.csv \
  -k 15 -e 1e-20 -p 90 -q 90
```

### Skip prodigal using a pre-computed protein FASTA
```bash
./mobileOGs-pl-kyanite.sh \
  -i test.fasta \
  --faa test.faa \
  -o ./results \
  -d mobileOG-db-beatrix-1.X.dmnd \
  -m mobileOG-db-beatrix-1.X.All.csv \
  -k 15 -e 1e-20 -p 90 -q 90
```

### Display help
```bash
./mobileOGs-pl-kyanite.sh -h
```
